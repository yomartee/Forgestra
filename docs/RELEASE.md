# Release policy

Experimental source upload is separate from main-branch merge, package publication
and a tagged release. Source upload needs exact contents/confidentiality and rights
disposition, applicable notices/metadata, reporting evidence and accurate policy,
technical acceptance, canonical-ancestor reconciliation and explicit named-action
authorization. Uncertain rights are not waived by owner contents approval.

The owner approved attempt4's experimental local CLI/library and optional read-only
stdio MCP scope. Independent review was not performed; the owner's exact attempt4
exception concerns only a future separately authorized named-review-branch source
upload. Changed bytes require explicit successor applicability review, including
that exception. No review is fabricated and actual GitHub rules must not be bypassed.

Hosted CI follows an authorized first upload: local commands are not GitHub check
runs. Merge/release require their separately applicable eligible review, successful
real checks at the intended SHA, permissions/protection enforcement, advisory
applicability and final acceptance. No hosted success is inferred. Reporting's
harmless owner-reported test is bounded evidence, not proof of ongoing response
or resolution ability; see [security](../SECURITY.md).

Version remains 0.2.0.dev0. No tag, namespace reservation, package upload or release
is authorized. Any later RC needs a separately reviewed version change, exact
integrated commit/tree and wheel/sdist/SBOM digests, clean-install replay and known
experimental limits. Re-run affected checks after material byte changes; do not
reuse old acceptance for changed bytes.

Gate A is an intermediate experimental source option, not production certification.
Gates B/C require the missing [runtime boundaries](RUNTIME_BACKLOG.md) and separately
authorized live sandbox/generated-app/fleet acceptance. CLI/stdio needs no VPS.
R1 has not started. Privileged automation stays disabled.

Rollback means preparing a reviewed source revert on a new branch and retaining
previous reviewed artifacts, not force-push, reset or customer deletion. Private
retained-version selection is not deployed service/database recovery. See
[provenance](PROVENANCE.md).
